# Product feedback — local prototype scope

Tools: MCP official SDK2.3.0 implements the Streamable HTTP server and tested SDK client. The consumer standard JSON-RPC client records real initialize/initialized/tools/list/tools/call. Chrome/CDP supplies pinned native media and compositor capture. FFmpeg via imageio-ffmpeg0.6.0 validates and decodes local source references and encodes the disclosed movie.

What worked: local MCP JSON-mode negotiation, actual tool schemas/results, independent observer subprocesses, owned browser targets and packaged offline Windows dependencies make the behavior reproducible without model credentials.

What needed work: the R13 application trusted decoded hidden media, retained stale consent and persisted ephemeral endpoints. These were self-authored application defects, not SDK failures. A whole-request lock in the consumer client delayed Stop; the application now locks only request IDs and transcript writes. CDP navigation can invalidate frontend node IDs; launch acquisition is bounded and observer sampling pins backend identity.

Onboarding: setup validates Python/browser prerequisites and installs a frozen offline wheelhouse. It then runs actual protocol and media tests. Source/build/film evidence is separated from a successful pip install.

Would we build again: yes for a scoped local proof. Physical devices and native Alexa require separate qualification. No friction bonus is claimed. Any future friction entry must include a reproducible SDK/API problem, its expected/actual behavior and actionable feedback; self-authored defects are clearly labeled.
